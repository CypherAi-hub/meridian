# Local research paper runner

This source implements a separate prospective research PAPER book. It is not connected to Engine scheduling, discovery enrollment, the dashboard, a signer or funded trading. It has not yet run on actual market quotes. Its passing synthetic lifecycles are operation checks, not profitable-strategy evidence.

The implementation shares PaperLedger's entry settlement, inventory, fee allocation, marks, partial exits, protective exits and accounting. The strict fill adapter still requires its original strict verdict. The research adapter reruns the frozen research policy against original decision evidence at settlement and obtains a structurally separate research capital authorization. Both use a single economic risk kernel; the original strict verdict is never forged. Each book's mode is immutable. A WeakMap issuance registry binds a one-use authorization to its exact proposal and governor. Consumption and financial mutation are synchronous.

Use the existing owning worker's Store and its existing shared Jupiter quote provider/lane. Do not create a second provider client to evade capacity. Freeze a new policy and run manifest before prospective enrollment; bind the real SHA256 source fingerprint. The run freezes capital, policy, population, enrollment interval, every economic risk limit and exit rule, and fee/rent/failure/provider assumptions. V1 remains readable as V1; V2 requires the original seven-field raw mint capture and does not certify hidden ownership.

The service integration API is:

- `freezeResearchPaperRun({bookId,policy,enrollmentStart,enrollmentEnd})` creates an immutable manifest. Freeze after source is finalized, before enrollment begins.
- `ResearchPaperRunner.create(store,existingQuoteProvider,manifest)` creates a new book only. It refuses an existing key and late creation.
- `ResearchPaperRunner.restore(store,existingQuoteProvider,manifest)` resumes only an existing exact identity. Missing or mismatched state stops; it never falls back to a new 1 SOL balance. Current marks are invalidated durably on restart.
- `await runner.enroll(originalDecision)` saves the original features, security and raw mint capture plus delayed intent before any quote I/O. Its single occupied slot and reserved principal/fee are durable. Original feature times/costs remain unchanged.
- `await runner.step()` manages positions and ready protective exits first, then eligible delayed entry. It performs at most two quote calls per step, preserving actual request/response times, requesting exact bought minimum quantity on the paired sell, and rerunning final admission/risk checks. The paired entry sell is not the eventual exit.
- `runner.accountState()` returns separately labeled cash, reserved and available cash, unknown/fresh equity, realized paper P&L, settled modeled fees, positions/intents and identities. `snapshot()` returns a detached complete book envelope.

Store must enforce the worker lease. Every book save also uses an atomic expected-version and manifest match in the database. Two runner instances sharing one worker lease cannot overwrite each other. A stale instance, reconciliation failure, ambiguous write acknowledgement or lost lease suspends that instance; restore durable state before continuing. No authorization is serialized for later reuse.

Each economic mutation and its evidence/journal use one captured settlement timestamp. Quotes are detached once from provider results, preventing later mutation or accessor changes. Every mark and exact exit intent is retained, including identity, reason, size, delay and supersession. Failed exit quotes retain full inventory/intents and unknown marks. Entries that expire or fail before modeled submission become explicit cancellations with no invented fill or chain fee. A partial profit exit cannot suppress a later full max-hold or emergency intent.

An independent reconstruction checks enrollment chronology and original decision/capture identity, complete admitted entry quote identity, exact quote size/slippage/impact/source/router/RFQ/freshness on marks and exits, typed monotonic journal transitions, outstanding protective intents, proportional basis and entry-fee allocation, cash, remaining quantity, final legs, order IDs and capacity. It rejects lost stop intents and internally contradictory saved quotes. This verifies internal consistency conditional on captured evidence; it does not authenticate RPC/provider responses.

Network fees are explicitly modeled at 10,000 lamports per settled leg. Priority cost is assumed included in that fixed model. No on-chain token account is created; rent is excluded. No transaction is submitted; on-chain failed-submission fees are excluded. Those limitations are hashed into the run manifest and must be visible with every result. They prevent treating this run as proof of attainable live net returns.

Actual runtime integration remains required: enroll new causally available decisions from discovery, use the native raw mint-capture producer, propagate kill/stop controls, schedule behind existing provider reservations, expose the separate experimental book in Omni, and verify an actual prospective quote lifecycle. The active frozen forward experiment must not be silently replaced. A source rollout must retire any interrupted epoch explicitly as incomplete and start a new frozen identity, preserving every old manifest/journal/cutoff. An untouched performance cohort including negative and unresolved outcomes is still required. Real funding and private payout conversion remain disabled.
