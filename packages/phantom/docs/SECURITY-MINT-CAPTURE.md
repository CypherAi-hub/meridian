# Original mint-account capture

New `SecurityReader.inspect()` results retain an optional `mintAccountCapture` on `SecuritySnapshot`. It records the exact requested mint address, validated account owner, canonical original base64 data and finalized RPC context slot. Raw mint captures are limited to 65,536 bytes. The separate research decoder must still validate mint/TLV framing, extension scope and payloads; retaining bytes does not certify them. The existing `extensionsVerified` summary is not a substitute for that decoder.

`requestedAt` is sampled immediately before the mint `Rpc.call` invocation. It includes any internal queue wait; it does not certify HTTP transmission start. Capture `observedAt` is sampled when that call returns, before pool/holder inspection. `publishedAt` is sampled when the whole inspection result is complete. The snapshot and safety evidence use that same final publication timestamp. The immutable capture retains the earlier raw-response timestamp and original bytes even if later work changes the source response object. Invalid or regressed clocks reject. An unsupported owner returns unverified evidence without a mint capture; other mint-account/decode failures return no completed snapshot. No extra provider calls or metadata URI requests are added. An encoded-length check precedes base64 decoding, followed by an exact decoded-size check; this bounds mint decoding/retention, but not the earlier RPC JSON response allocation.

`evidenceRequestedAt` retains the earlier inspection start as the safety freshness anchor. **This producer requires the paired `TokenSafetyEvidence.evidenceRequestedAt` freshness guard in `risk.ts`.** The strict guard must reject malformed anchors or request-after-publication ordering, age evidence from the original request and derive expiry from that request. Publication must never renew the age of old mint controls. The Mac integration owns this guard; a matching local mirror was used for producer validation and is intentionally excluded from the producer commit. The long-inspection regression retains its stale-evidence assertion.

Old snapshots have no capture and cannot be certified retroactively. The flattened replay format still lacks original bytes; this component does not rewrite that format, introduce a paper runner, create a strict entry exception or activate any policy. Neither RPC response authenticity nor hidden creator relationships are independently proven. The active frozen worker and its existing records remain unchanged.
